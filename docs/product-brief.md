# سبرنت (Sprint) — فكرة المشروع وتفاصيله

> الوصف الأصلي اللي بدأ منه المشروع. لو فيه تعارض بينه وبين `BRD.md` أو `decisions.md`، الاتنين دول هما المرجع.

## الفكرة في جملة

تطبيق Flutter (أندرويد / iOS / ويب) لحجز المنشآت الرياضية بجامعة طنطا، بيحوّل الحجز العشوائي والتحصيل النقدي لنظام إلكتروني عادل ومتتبَّع. وهو في نفس الوقت أداة الدراسة الثالثة في رسالة الدكتوراه بتاعة د. سارة الحاج (قسم الإدارة والترويج الرياضي، تربية رياضية طنطا).

عنوان الرسالة: *تطبيق إلكتروني لإدارة وتسويق المنشآت الرياضية بجامعة طنطا كنموذج تطبيقي للإدارة الإلكترونية*

## المشكلة اللي بيحلها

- حجز عشوائي وإجراءات ورقية/تقليدية، وزحمة (زي حمامات السباحة).
- مفيش قاعدة بيانات دقيقة لمعدلات الاستخدام.
- صعوبة تعريف المستفيدين بالمنشآت والأوقات الفاضية، وضعف التسويق.
- مفيش تطبيق يربط الإدارة بالمستفيدين.
- الأوقات المسائية والإجازات مش مستغلة تجاريًا.

## الأدوار

- **الحاجز (Booker):** طالب / موظف / عضو هيئة تدريس (سعر مخفّض موحّد) أو زائر خارجي (سعر كامل). السعر بيتحدد تلقائيًا من نوع الحساب، مش يدويًا.
- **المدرب (Trainer):** يتابع الحضور بمسح QR مع بديل يدوي.
- **الأدمن (هرمي بواجهة واحدة وصلاحيات متدرجة):** مدير منشأة، عميد، ممثل الوزارة. *(اتعدل في الـ BRD: الأدوار بقت دور × نطاق، وممثل الوزارة اتشال.)*

## الـ User Flow (4 مراحل)

1. **الدخول والتحقق:** تحديد شريحة السعر من نوع الحساب.
2. **تصفح المنشآت واختيار الوقت:** فحص التوفر فوري ومنع التعارض.
3. **التأكيد والدفع:** نجاح يؤكد الحجز ويبعت إشعارات، وفشل يرجّع للمحاولة.
4. **بعد الحجز:** شاشة تأكيد (رقم الحجز + QR + التفاصيل)، إشعار و SMS، تذكير قبل ساعة مع إمكانية الإلغاء، وتسجيل حضور/غياب يوم الحجز، وتحديث تقرير الأدمن تلقائيًا. *(الـ SMS اتأجل لـ P2.)*

## قرارات UX أساسية

- الهوم حسب الحالة (زائر = اكتشاف، مسجّل = مخصص).
- نافذة حجز 7 أيام، والأوقات الماضية معطّلة.
- المنشآت المجانية: نطاق ساعات متعدد.
- المنشآت بمدرب (زي السباحة): اختيار المدرب أولًا ثم slots ساعة ثابتة، ومساران منفصلان.
- حضور المدرب بـ QR مع fallback يدوي.
- اللغة: عربي RTL أساسي، وإنجليزي ثانوي، ولهجة مصرية خفيفة في النصوص.
- اللوجو: برق (bolt).

## التقنية وطريقة الشغل

- **Stack:** Flutter + Riverpod (codegen) + Freezed + GoRouter + Clean Architecture. (الـ backend بعد الواجهة.)
- **Spec Kit** بترتيب صارم: specify → clarify → plan → tasks → implement، مع قسم **Out of scope** إجباري في أي feature UI-only.
- **الأدوات:** OpenCode للتنفيذ، Claude Code للتخطيط والمراجعة.
- **Git:** فرع و PR لكل feature، ومفيش rewrite للتاريخ.
- **CI/CD:** نشر `develop` على GitHub Pages.

## ملخص الـ User Stories

**الحاجز**
- كزائر، أتصفح المنشآت وأشوف التوفر من غير حساب.
- كطالب/موظف، أسجّل دخول وأشوف السعر المخفّض تلقائيًا.
- كحاجز، أختار منشأة ووقت (في حدود 7 أيام) وأتأكد إن مفيش تعارض.
- كحاجز، أحجز نطاق ساعات في المنشآت المجانية.
- كحاجز، أختار مدرب ثم slot في المنشآت بمدرب.
- كحاجز، أدفع إلكترونيًا وأستلم رقم حجز و QR وإشعار.
- كحاجز، أستلم تذكير قبل ساعة وأقدر ألغي لو الوقت يسمح.
- كحاجز، أشوف حجوزاتي وإشعاراتي وبروفايلي.
- كزائر خارجي، أحجز بالسعر الكامل.

**المدرب**
- أمسح QR الحاجز لتسجيل الحضور، أو أسجّله يدويًا لو فشل المسح.
- أشوف قائمة الحضور والداشبورد بتاعتي.

**الأدمن**
- كمدير منشأة، أراقب الحجوزات وأسجّل الحضور/الغياب.
- كعميد، أشوف KPIs وتقارير الإيراد بصلاحيات حسب مستواي.
- كأدمن، أدير الأصول (العهدة) وبلاغات التلف.

**الدخول**
- كأي مستخدم، أدخل بإيميل/موبايل وباسورد من فورم واحد، وأشوف حالة تحميل.
